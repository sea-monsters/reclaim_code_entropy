# Reclaim Code Entropy · 0.3.0

一个帮助代码代理发现、判断并实施有证据的化简的 skill。目标是减少需要长期维护的一致性负担：重复状态、多余接口、过度抽象、废弃兼容路径和配套残留，而不是追求最大删行数。

这是工作指引，不是独立运行的扫描器，也不提供语义等价或零回归保证。“熵”是维护负担的工程比喻，不是计算出来的熵值。当前版本为 **0.3.0**。

## 适合什么任务

- 审计仓库或指定模块，找出值得化简的候选及证据
- 删除确认无消费者的私有实现及其专用残留
- 保留公共契约，收敛仍在使用的转发层或重复表示
- 在产品决定和迁移责任明确后，完整退役能力或兼容路径

不用于一般缺陷、安全或性能审计；不会因为扫描器报“未使用”、没有仓库内调用或代码行数减少就批准删除。没有安全切口也是有效结果。

## 安装与使用

需要支持本地 `SKILL.md` 技能的宿主，以及该任务所需的仓库读取、编辑和验证工具。它没有需要安装的运行时依赖；执行项目检查仍取决于目标项目环境。

对于支持 `$CODEX_HOME/skills` 本地技能目录的 Codex 环境，可将本仓库克隆到以下目录。目录名使用技能名 `reclaim-code-entropy`，而不是仓库名中的下划线：

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
git clone https://github.com/sea-monsters/reclaim_code_entropy.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/reclaim-code-entropy"
```

若目标目录已存在，不要覆盖本地修改；先检查其来源、状态和差异。其他宿主请按其本地技能加载方式安装。不同产品或版本的加载方式可能不同；仓库不包含自动安装器。

在支持技能调用的会话中，明确给出模式与范围：

```text
使用 $reclaim-code-entropy 审计 src/jobs，只报告候选、证据和阻碍，不修改文件。

使用 $reclaim-code-entropy 化简 src/parser 中已证明安全的内部实现，保留公开接口与既有行为，执行必要验证并报告限制。

使用 $reclaim-code-entropy 移除已决定退役的 legacy-export 功能；支持窗口已结束，调用方已迁移。先核对这些前提，再实施范围内清理。
```

### 两种模式

- **审计**：只读检查并返回候选，不创建 TODO、提案文件或修改代码
- **执行**：在现有授权和仓库规则内实施安全切口、验证并报告；未明确的产品退役决定只阻断相关候选

模式按完整请求及已有授权判断。安装或调用本技能不授予额外权限，也不自动授权推送、发布或改变支持政策。

## 决策方式

先区分不可达删除、保留契约的活代码化简、能力／兼容性退役，再标为可实施、需要补证、需要决策或不成立。只有可实施项进入执行排序，收益不能抵消关键未知。

证据绑定当前版本、相关工作区变化、支持配置和搜索边界。截断、失败、遗漏生成源或过期索引都不能视为零命中；相关代码或假设变化后，需要刷新受影响证据。

候选决定、实施状态、验证结果分开记录：可实施不等于已实施，也不等于验证通过。

修改前确认存续契约与独立行为判据。不能靠同时删除实现和失败测试制造“全绿”。验证按风险选择最小反例检查，同时保留已有性能、数据兼容、信任边界和异步生命周期义务。

结果区分通过、失败、不可用和未运行。关键验证不可用时，契约敏感删除保持为提案；低风险局部改动也必须明确验证限制。保护他人修改，失败时只修复或撤回当前批次。

## 0.3.0 的重点

本版将已有规则落实为轻量、可复现的执行支撑：

- 独立行为判据检查副作用、输入访问与求值顺序，而不只是返回值
- 评测分别报告行为保持、结构完成度、审计写入、无关改动与判据完整性，避免“全绿但没完成”
- 可选批量搜索工具记录范围、结果完整性、错误和未解析入口；无匹配不自动等于无消费者
- 按需读取转发层、镜像状态、生命周期三类证明配方

这些工具仅为证据支撑，不自动批准删除，也不执行目标仓库的任意命令。评测涉及导入受信任夹具代码，不是恶意代码沙箱；须先审阅候选代码。

## 按问题规模选择证据

- 私有、封闭、无边界义务的局部切口：定义／调用方核查、定向搜索和最小决定性测试即可，不强制 JSON、全量清单或全套回归
- 涉及共享调用、动态配置或既有性能预算：追加受影响入口、配置及集成检查，复用仍有效的证据
- 涉及公共兼容、持久化、鉴权或异步生命周期：追加对应独立边界判据；产品退役决策仍需明确

只由实质未知、承重义务或失败检查触发升级；义务已得到支持后停止扩查。评测器是技能维护者的回归工具，不要求每次使用技能都运行整个评测库。

夹具基线检查只需要 Python 3 标准库：

```sh
python3 -B evals/check_contracts.py
# 扩展评测和搜索工具测试（需要已安装 rg）
python3 -B evals/run_tests.py
```

这条命令检查夹具的存续行为，不调用模型、不证明 skill 遵循率，也不是旧版／新版 A/B 实验。0.3.0 的新增检查及实测边界见 evals/README.md；不能据此宣称生产误删率或维护成本已经降低。真实仓库的动态入口、外部消费者和配置覆盖仍可能不完整；请审查实际 diff 与验证证据。

## 设计依据

本次改进参考了 [SCARF](https://yia.nnis.gr/publications/fse2023.pdf) 的清理证据与依赖边界、[CodeTaste](https://proceedings.mlr.press/v306/thillen26a.html) 对重构发现和验证的评价，以及 [Echoes of AI](https://link.springer.com/article/10.1007/s10664-026-10889-1) 对后续维护成本的研究。这些工作帮助形成可检验的设计选择，不是技能效果的证明；论文不属于运行时必读上下文。
